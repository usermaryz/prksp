# Анализ предметной области

В учебном проекте рассматривается небольшой склад (или зона хранения товаров в магазине/Центре выдачи). В повседневной работе постоянно встречаются такие задачи:

- принять на учёт номенклатуру (товары с артикулом и остатком);
- оформить заказ клиента (ФИО, телефон, адрес доставки);
- выделить задачу на сборку и пройти её по статусам;
- передать собранный заказ в отгрузку (создание отправления у условного перевозчика);
- держать в поле зрения загрузку зон склада и базовые метрики на «главной».

Пользователи системы по смыслу делятся на роли: администратор/менеджер (ведут каталог и документы), сборщик (работает с задачами комплектации), водитель/курьер (в реальности чаще смотрит статусы доставки — в нашем учебном API доступ к части операций ограничен отдельно). Это нужно не «для красоты», а чтобы не дать случайному сотруднику сменить критичные данные.

Границы проекта сознательно узкие: это не полноценный коммерческий WMS, а учебный fullstack с CRUD, авторизацией и проверкой прав.
