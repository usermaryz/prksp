# Обоснование выбора технологий

**Клиент.** React выбран как распространённый стек для SPA: компонентный подход, быстрый старт, много примеров в учебных материалах. TypeScript дисциплинирует типы на границе с API. Стили — Tailwind (уже был в проекте), чтобы не писать «ручной» CSS на каждую кнопку.

**Сервер.** FastAPI на Python — короткие handler-функции, автодокументация OpenAPI «из коробки», удобные зависимости (`Depends`) для авторизации. Для курсовой это плюс: проще показать слои «роутер → бизнес-правила → БД».

**База данных.** SQLite: один файл, не нужно поднимать отдельный сервер БД на ноутбуке одногруппника. В Docker при необходимости путь к файлу кладётся на volume, чтобы данные не терялись при пересборке контейнера.

**Сборка и развёртывание.** Dockerfile для backend и frontend (nginx отдаёт статику). `docker-compose.yml` связывает сервисы. Это закрывает требование про контейнеризацию без лишней «облачной магии».

**Контроль версий.** Git в папке `prksp` — стандартная практика, к публикации репозитория на GitHub/GitLab можно добавить ссылку в пояснительную записку.
