# Развёртывание в облаке (варианты для курсовой)

Ниже — рабочие схемы без привязки к одному провайдеру. Для защиты достаточно: «поднял VM / PaaS, открыл порты, выставил переменные окружения, приложил скриншот».

## Вариант A: одна виртуальная машина (проще всего)

1. Создать VPS (Timeweb, Selectel, Yandex Cloud «Compute», и т.п.).
2. Установить Docker + docker compose plugin.
3. Склонировать репозиторий с `docker-compose.yml`.
4. На сервере задать `SECRET_KEY` (длинная случайная строка) и при необходимости `REACT_APP_API_URL` так, чтобы из браузера был доступен ваш API (часто `http://<ip>:8000/api` или домен с reverse-proxy).
5. Запуск: `docker compose up -d --build`.
6. Внешне открыть порты **80** (frontend) и **8000** (API) либо поставить nginx/caddy как reverse proxy на один домен.

Замечание по безопасности: в проде лучше HTTPS (Let's Encrypt) и отдельный секрет для JWT.

## Вариант B: Railway / Render / Fly.io

Идея та же: один контейнер с API + отдельно статика, либо два сервиса. Важно прописать:

- `SECRET_KEY`
- `DB_URL` (или volume, если платформа позволяет)

На бесплатных тарифах иногда нет постоянного диска — тогда SQLite «обнулится» после сна сервиса; для курсовой это обычно терпимо, если в записке честно написать ограничение.

## Что написать в пояснительной (коротко)

- какой вариант выбрали и почему (цена/простота/наличие студенческого промокода);
- какие порты и переменные среды использованы;
- скриншот рабочей страницы и ответ `/health`.
