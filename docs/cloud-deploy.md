# Развёртывание в облаке

Ниже — практические варианты для курсовой: **одна VM с Docker**, **Render (PaaS)** по `render.yaml`, кратко **Yandex Cloud**. Для защиты приложите скриншот рабочего интерфейса и ответ `GET …/health`.

---

## Вариант 1: одна виртуальная машина + Docker (рекомендуется по простоте)

Подходит для Timeweb, Selectel, Yandex Compute и т.п.

1. Установить **Docker** и плагин **Compose**.
2. Склонировать репозиторий, в корне задать секрет:
   ```bash
   export SECRET_KEY="$(openssl rand -hex 32)"
   ```
3. Запуск **production-ориентированного** compose (веб на **порту 80**, API только во внутренней сети, фронт собран с `REACT_APP_API_URL=/api` — запросы идут на тот же хост, nginx проксирует `/api` на контейнер API):
   ```bash
   docker compose -f docker-compose.prod.yml up -d --build
   ```
4. В фаерволе провайдера открыть **TCP 80** (и при необходимости 22 для SSH).
5. В браузере открыть `http://<публичный-IP>/` и проверить вход демо-пользователем.

HTTPS и домен: поставить **Caddy** или **nginx** на хосте с Let's Encrypt и проксировать на `127.0.0.1:80` — в записке достаточно ссылки на стандартную схему.

## Вариант 2: Render.com (blueprint из репозитория)

В корне репозитория лежит **`render.yaml`**: два web-сервиса Docker — **prksp-api** (FastAPI) и **prksp-web** (статика + nginx).

1. Зарегистрироваться на [Render](https://render.com), подключить GitHub/GitLab.
2. **New → Blueprint** → выбрать репозиторий и ветку с `render.yaml`.
3. Дождаться сборки обоих сервисов. Публичные URL вида `https://<имя-сервиса>.onrender.com`.
4. В файле blueprint задано:
   - у API переменная **`CORS_EXTRA_ORIGINS=https://prksp-web.onrender.com`** (разрешённые запросы с фронта);
   - при сборке фронта **`REACT_APP_API_URL=https://prksp-api.onrender.com/api`** (браузер обращается к API по публичному URL; блок `location /api/` во фронтовом nginx на Render не используется — это нормально).

Если имена сервисов на Render пришлось изменить (имя занято), синхронно обновите в `render.yaml` значения `CORS_EXTRA_ORIGINS` и `REACT_APP_API_URL` и сделайте redeploy.

**Ограничение бесплатного tier:** инстансы «засыпают», файловая система эфемерная — **SQLite без подключённого диска** может обнуляться после сна. Для курсовой это нормально, если в тексте явно указано. Платный **Disk** в Render можно смонтировать в `/app/data` у API (см. документацию Render → Disks).

## Вариант 3: Yandex Cloud (кратко для записки)

Общая схема: **Compute Cloud** (ВМ с Ubuntu) → установка Docker → запуск как в варианте 1; либо **Container Registry** + **Serverless Containers** / **Managed Service for Kubernetes** для более «облачного» но более трудоёмкого сценария. Для учебного проекта достаточно **одной ВМ + `docker-compose.prod.yml`**.

---

## Переменные окружения (сводка)

| Переменная | Где | Назначение |
|------------|-----|------------|
| `SECRET_KEY` | API | Секрет подписи JWT (обязательно не дефолт в облаке). |
| `DB_URL` | API | По умолчанию SQLite в `/app/data` в Docker. |
| `CORS_EXTRA_ORIGINS` | API | Список origin через запятую для браузера (Render: URL фронта). |
| `REACT_APP_API_URL` | Сборка фронта | Базовый URL API (`/api` на одной VM за nginx или полный `https://…` на Render). |

## Что приложить к отчёту

- Скриншот главной страницы приложения в облаке.
- Скриншот или текст ответа **`GET /health`** (`{"status":"ok"}`).
- Краткое описание выбранного варианта и ограничений (бесплатный tier, HTTPS, персистентность БД).
