# План презентации (≈10–12 слайдов)

Каждый слайд: заголовок + 1 скрин/диаграмма + 3–5 буллетов текста максимум.

1. Титульный: тема курсовой, ФИО, группа, город/вуз (как требует кафедра).
2. Зачем система: 2–3 боли склада без учёта (потери, статусы, ручная бумага).
3. Цели и границы: что входит в проект и что сознательно не делали.
4. Анализ предметной области: роли пользователей, основные объекты (товар, заказ, отправление).
5. Архитектура: клиент–сервер, схема из `docs/uml.md` (компоненты).
6. Стек: React + FastAPI + SQLite + Docker (почему так — см. `docs/tehnologii.md`).
7. Авторизация: логин, JWT bearer, таблица «кто что может» (или скрин ответов 403).
8. База данных: логическая схема (нарисовать вручную 5–8 сущностей).
9. Демонстрация UI: скрин «главной», «товаров», «логистики».
10. Тесты: фаззинг `tools/fuzz_api.py` — что проверяли, пример лога.
11. Развёртывание: docker compose / облако (скрин).
12. Итоги и направления развития (PostgreSQL, RBAC тоньше, аудит).

Графика: 2–3 диаграммы UML (компоненты + последовательность), 3–4 скрина интерфейса, 1 схема деплоя.
